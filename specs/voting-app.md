# Spec: 동아리 투표 앱과 4주차 기능 추가

## Problem Statement

동아리 운영자는 구성원의 의견을 한곳에 모으고 싶다. 투표가 무기한 열려 있으면 참여 시점이 불명확하고 숫자 목록만으로는 결과를 파악하기 어렵다.

## Solution

운영자가 질문·선택지·선택적 마감 시간을 등록한다. 구성원은 계정 없이 하나를 선택한다. 참여 후 결과를 득표수와 비율 막대그래프로 확인한다. 운영자는 모든 투표와 0표 결과를 볼 수 있다.

## User Stories

1. 운영자로서 비밀번호로 로그인해 투표 관리 화면을 안전하게 열고 싶다.
2. 운영자로서 질문과 선택지 2~10개를 등록하고 싶다.
3. 운영자로서 마감 시간을 선택하거나 비워둘 수 있어야 한다.
4. 운영자로서 투표를 삭제하기 전에 확인을 받고 싶다.
5. 투표자로서 공개 목록에서 현재 투표를 찾고 싶다.
6. 투표자로서 선택지 하나에 한 번 투표하고 싶다.
7. 투표자로서 이미 참여했다면 다시 제출하지 않고 결과로 이동하고 싶다.
8. 투표자로서 마감된 투표의 버튼과 안내를 보고, 서버도 제출을 거부하길 원한다.
9. 참여자로서 결과를 수와 비율 막대그래프로 보고 자동 갱신되길 원한다.
10. 운영자로서 참여자가 아직 없어도 0표 결과를 확인하고 싶다.
11. 제출자로서 앱 화면에서 제작자 이름을 확인할 수 있어야 한다.

## Implementation Decisions

- Next.js App Router, TypeScript, Route Handlers, Neon Postgres의 매개변수화된 SQL을 쓴다.
- `polls`는 nullable `closes_at`을, `options`는 정렬 순서와 득표수를, `votes`는 투표자 쿠키 ID에 대한 투표별 유일 제약을 가진다.
- 투표 기록 삽입과 득표수 증가는 단일 DB 명령으로 처리한다. 서버 시각으로 마감을 확인한다.
- 결과 API와 페이지 모두 참여 여부 또는 운영자 인증을 확인한다.
- DB 연결이 없는 로컬 PC에서는 파일 기반 체험 모드가 작동한다. Vercel에서는 Neon이 필수다.
- 앱의 제작자 표시는 `이이삭`이다.

## Testing Decisions

- 공개 API를 통한 생성·중복 제출·마감 거부·결과 접근 제한·삭제를 검증한다.
- 타입 검사, 린트, 프로덕션 빌드와 실제 브라우저 흐름을 확인한다.
- 0표 막대그래프는 운영자 미리보기에서 확인한다.

## Out of Scope

투표자 계정, 다른 기기까지 묶는 중복 방지, 복수 선택, 다중 운영자, 결과 내보내기, 실제 선거 수준의 부정행위 방지.

## Further Notes

수업자료 초반의 2~5개 선택지·단순 스키마 예시보다 후반의 완성 예시(2~10개, 운영자 인증, `votes`)를 우선했다. 과제 안내의 세 기능을 그 위에 추가했다.
